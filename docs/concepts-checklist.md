# Concept checklist: where each idea is explained

Everything a customer needs to integrate a site or write a plugin is explained inside this repository. This
page is the index, and the test: if you can not find a concept below, or the linked section does not answer
it, that is a documentation bug. Open an issue.

| Concept | What you need to know | Explained in |
|---|---|---|
| Host registration | A host is registered by the platform operator (request access); you get back `apiBaseUrl`, `hostId`, `tenantId`, a host API key and a webhook secret. Registered origins control framing and CORS | [README "Get access"](../README.md#get-access), [integration guide section 1](integration-guide.md#1-what-you-need-from-us), `register-host` / `add-host-origins` in [`tools/sample-bootstrap`](../tools/sample-bootstrap/HandOfClient.SampleBootstrap/Program.cs) |
| API keys | Host API key (`x-api-key`, server side only, returned once) vs the operator's super-admin key (`x-hoc-host` selects the host); rotation | [platform API, Authentication](../openapi/platform-host-v1.yaml), [integration guide section 1](integration-guide.md#1-what-you-need-from-us), `rotate-api-key` in [`tools/sample-bootstrap`](../tools/sample-bootstrap/HandOfClient.SampleBootstrap/Program.cs) |
| Tenants | The unit of isolation inside a host; storage, activations, secrets and allowlists are all per tenant; a WordPress site uses its own host name | [platform API, Authentication](../openapi/platform-host-v1.yaml), [WordPress host](wordpress-host.md), [integration guide](integration-guide.md) |
| Packages and slots | A package is a published plugin; a slot is where one of its entry points mounts (`panel`, `page`, `override`); activation binds a version to `{host, tenant, slot}` | [plugin tutorial section 3](plugin-author-tutorial.md#3-write-the-manifest-manifestjson), [page lookup](page-lookup.md), [WordPress host](wordpress-host.md) |
| Manifest schema | Author-facing `manifest.json` and the wire `Manifest` it becomes; validated by `hoc-publish` | [plugin tutorial section 3](plugin-author-tutorial.md#3-write-the-manifest-manifestjson), [`proto/handofclient/v1/package_registry.proto`](../proto/handofclient/v1/package_registry.proto), [`tools/publisher-cli/src/authorManifest.ts`](../tools/publisher-cli/src/authorManifest.ts) |
| Scopes | Capabilities the manifest declares; copied into the embed token's `scope` claim, never caller-supplied | [plugin tutorial section 3](plugin-author-tutorial.md#3-write-the-manifest-manifestjson), [platform API, Embed token JWT](../openapi/platform-host-v1.yaml) |
| Embed tokens and refresh | Short-lived ES256 JWT minted by the host's token endpoint; refreshed through the host page | [no-source integration section 2.2](no-source-integration.md), [protocol 5.7](postmessage-protocol.md#57-hoctoken-refresh-plugin---host-requestreply), [protocol 9.2](postmessage-protocol.md#92-hosts-tokenurl-endpoint-contract) |
| JWKS | Public keys at `/host/v1/jwks` for verifying embed tokens locally | [platform API, jwks operation and Embed token JWT](../openapi/platform-host-v1.yaml), [integration guide section 3](integration-guide.md#3-the-three-functions-you-write) |
| Egress proxy and secrets | `hoc.http.send` is the only outbound door; allowed hosts = manifest `egressHosts` intersected with the tenant allowlist; `{{secret:name}}` and `{{hoc:token}}` substitution; private IPs blocked | [platform API, Placeholders substituted by the egress proxy](../openapi/platform-host-v1.yaml), [plugin tutorial section 2](plugin-author-tutorial.md#2-write-the-plugin-srcindexts), [no-source integration section 3](no-source-integration.md), [WordPress host section 2.2](wordpress-host.md) |
| Webhook signing | `sha256=` + hex HMAC-SHA256 of the raw body with the host's webhook secret; event types and replay protection | [integration guide section 5](integration-guide.md#5-webhooks), [site API, `/webhook` operation](../openapi/site-hoc-api.yaml) |
| Versions, pinning, rollback, withdraw | Versions are immutable; publish does not activate; `Activate` / `Pin` / `Rollback` / `SetSlotEnabled` move the pointer; a withdrawn version answers `409` | [plugin tutorial section 5](plugin-author-tutorial.md#5-publish-for-real), [platform API](../openapi/platform-host-v1.yaml) |
| Hygiene checks and limits | What `hoc-publish` scans, why it is not the security boundary, bundle size limits | [plugin tutorial, Hygiene checks](plugin-author-tutorial.md#hygiene-checks) |
| Security boundary | Sandboxed iframe, served CSP, origin pinning, server-side binding to `{host, tenant, package}` | [README "Security model"](../README.md#security-model), [protocol sections 3 and 7](postmessage-protocol.md), [integration guide, Content-Security-Policy](integration-guide.md#content-security-policy) |
| iframe vs inject mode | Where the feature runs and what changes for the author | [plugin tutorial, Inject mode](plugin-author-tutorial.md#inject-mode), [page lookup](page-lookup.md) |
| Error codes | Two JSON error shapes on the platform API, the site API error table, mount error reasons, gRPC status codes | [platform API, Errors](../openapi/platform-host-v1.yaml), [site API, Errors](../openapi/site-hoc-api.yaml), [protocol section 6](postmessage-protocol.md#6-error-catalog-host-side-hocmounterrorreason), [integration guide, Troubleshooting](integration-guide.md#9-troubleshooting) |
| Customization requests | End users ask for a feature; the platform builds it; statuses and replies | [README "Let your users request features"](../README.md#let-your-users-request-features-the-customization-loop), [site API](../openapi/site-hoc-api.yaml), [components](components.md) |
| Host modules for your language | Node, PHP and Python modules plus the conformance suite for any other language | [integration guide section 8](integration-guide.md#8-your-language-has-no-host-module), [`host-modules/conformance`](../host-modules/conformance/README.md) |
